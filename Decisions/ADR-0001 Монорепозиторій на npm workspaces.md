# ADR-0001. Монорепозиторій на npm workspaces

## Контекст

Застосунок має фронтенд, бекенд і спільні схеми та доменну логіку. Агент має бачити всю кодову базу в одній робочій директорії, а зміни схеми мають одночасно потрапляти в обидві частини.

## Рішення

Один репозиторій `whats-in-the-fridge` з npm workspaces: `apps/web` ([[Веб-клієнт]]), `apps/api` ([[API-сервер]]), `packages/shared` ([[Спільний пакет]]). Кореневі скрипти: `dev`, `build`, `test`, `lint`, `typecheck`.

## Розглянуті альтернативи

- Окремі репозиторії фронтенду й бекенду — дублювання типів, агенту потрібні дві робочі директорії.
- pnpm / Turborepo / Nx — потужніші, але додають інструмент, який треба встановлювати окремо; для трьох пакетів зайве.

## Наслідки

- (+) Одна команда запуску (NFR-07), атомарні коміти через усі шари.
- (+) Чіткі межі пакетів дозволяють архітектурні [[Guardrail|guardrails]] на рівні імпортів.
- (−) Без кешування збірки; прийнятно для розміру проєкту.
