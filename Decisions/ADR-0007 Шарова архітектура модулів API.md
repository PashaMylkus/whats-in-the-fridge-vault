# ADR-0007. Шарова архітектура модулів API

## Контекст

Агент генеруватиме однотипні модулі (задача T-01 harness). Щоб результат був передбачуваним і перевірюваним, кожен модуль [[API-сервер|API-сервера]] має однакову структуру.

## Рішення

Кожен модуль складається з шарів `router → service → repository`:

- **router** — HTTP, валідація zod, `requireAuth`; не звертається до Prisma;
- **service** — бізнес-правила, транзакції, виклики функцій зі [[Спільний пакет|спільного пакета]];
- **repository** — єдине місце доступу до Prisma; кожен запит фільтрується за `userId`.

Імпорти лише згори вниз; `repository` не імпортує `service` чи `router`.

## Наслідки

- (+) Скелет модуля генерується за шаблоном (skill `scaffold-module`), порушення шарів виявляється рев'ю.
- (+) Ізоляція даних [[Користувач|користувачів]] гарантується в одному шарі.
- (−) Для простих CRUD-модулів (наприклад, [[Модуль списку покупок]]) шар service частково дублює repository.
